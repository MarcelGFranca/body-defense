# AGENTS.md

Guide for AI agents and new contributors working on **Body Defense**: a portrait Android tower defense in Godot 4.7 (GDScript). The human body defends itself against viruses and bacteria. Enemies walk along veins, towers are immune cells, and the currency is amino acids.

Read this file first, then the doc that matches your task:

| Need | Read |
|---|---|
| What the product is, who plays it, what is in and out of scope | `docs/scope.md` |
| How the code is organised and how a game runs | `docs/architecture.md` |
| Rules: towers, enemies, damage, economy, waves, difficulty, progress | `docs/game-design.md` |
| Levels and bosses | `docs/levels.md` |
| Tests, bots, playtests, balancing, building the APK | `docs/development.md` |
| Every balance number, before and after, with playtest results | `design/balance.md` |
| Specs and tasks of each change | `openspec/` |

## Hard rules

- **Code, data and game text are in English.** The game will be translated later, so keep every player-facing string in one obvious place (data files, `menu.gd`, `hud.gd`, `tutorial_pages.gd`), pass it through `tr()` when it is shown, add it to `localization/translations.csv` (English text is the key; the test runner fails when a text has no translation), and never build sentences by concatenating pieces. The user talks to you in Portuguese; reply in Portuguese.
- **All balance numbers live in `tools/generate_data.gd`.** The `.tres` files in `data/` are generated output. Change the table, then run `godot --headless --path . --script res://tools/generate_data.gd`. Never hand-edit `data/`.
- **Commit and push only when the user asks.** Before every commit, document the task: its `openspec/changes/<name>/` (proposal, design, tasks, spec, with the tasks ticked), `docs/` pages that describe the changed behaviour, and `design/balance.md` when numbers changed. Code is not ready to commit until its documentation is.
- **Do not change balance without evidence.** Run playtests first (`docs/development.md`), show the analysis, and wait for approval.
- Match the surrounding code: tabs, `##` doc comment on top of each script, short comments, typed GDScript (`var x: int`, `-> void`), `class_name` for reusable types, no new autoloads without a reason (current ones: `Economy`, `GameAudio`, `Session`).
- Anything that depends on a level, tower, enemy or difficulty is data (`Resource` in `game/data/`), not a constant in code.
- Tests must pass before you finish: `godot --headless --path . --fixed-fps 60 res://tests/test_runner.tscn` (expected: `0 failures`).
- After adding or changing assets or scripts run `godot --headless --path . --import`.
- `build/` and `.godot/` are ignored. The debug APK goes to `build/body-defense-debug.apk`; raise the version in `export_presets.cfg` for every new build (SemVer name, numeric code: see `docs/development.md`).
- Every release adds an entry to `game/changelog.gd` (and its translations): the game shows it after an update and in Settings.
- Use `openspec/` for planned work: one change per feature, with `proposal.md`, `design.md`, `tasks.md` and spec deltas.

## Quick commands

```
godot --path .                                                                  # run (window 360 x 640, project size 720 x 1280)
godot --headless --path . --fixed-fps 60 res://tests/test_runner.tscn            # all tests
godot --headless --path . --script res://tools/validate_data.gd                   # data validation
godot --headless --path . --script res://tools/generate_data.gd                   # rebuild data/ from tools/generate_data.gd
godot --headless --path . --fixed-fps 60 -- --autoplay --level 5                 # a bot plays a level
godot --headless --path . --fixed-fps 60 res://tools/playtest.tscn -- --games 100 --out res://playtests/mine
python3 -I tools/analyze_playtests.py playtests/mine
```

## Map of the repository

```
assets/       sprites, UI, fonts, icon, sound effects and music (mostly generated by tools/*.py)
data/         generated .tres: enemies, towers, levels, difficulties, damage table, economy, audio
game/         all game code and scenes: scripts, splash.tscn (start scene), menu.tscn, main.tscn (one level); game/data/ holds the Resource classes
localization/ translations.csv (English key, one column per language)
tests/        test_runner.gd (one file, sections per feature)
tools/        generators, validators, bots, playtest runner, analysis, screenshots
design/       balance.md (generated) and design studies
playtests/    recorded bot games (games.jsonl, summary.csv, report.md)
openspec/     specs and change history
docs/         scope, architecture, game design, levels, development
```

## Common mistakes

- Editing `data/*.tres` by hand: it is overwritten the next time the generator runs.
- Forgetting `remove_child` before `queue_free` when swapping UI pages: Godot renames the new node and lookups by name fail.
- Scaling a spawned enemy's health twice: split copies pass `"final": true` so difficulty is not applied again.
- Judging a balance change from one run: 100 games per level is about ±10 points. Compare by level and by strategy, not by single numbers.
- Forgetting that the emulator is usable: it renders the game, see `docs/development.md` (Emulator) for the adb commands.
