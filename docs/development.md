# Development

## Setup

- Godot 4.7.2 on the PATH as `godot`.
- Python 3 for the generators and analysis (run with `python3 -I`).
- Android export: SDK, debug keystore and the arm64 template configured in `export_presets.cfg`.

## Tests

```
godot --headless --path . --fixed-fps 60 res://tests/test_runner.tscn   # about 450 checks, expect 0 failures
godot --headless --path . --script res://tools/validate_data.gd
```

`tests/test_runner.gd` has one `test_*` function per feature (data, damage, waves, economy, level, HUD, menu, difficulty, stats, audio). Add checks to the matching section. The secret level-select code (enemy x3, tower x2, enemy x1 on the menu) opens every level for manual testing.

## Bots and playtests

- `--autoplay [--level N] [--call-waves]` runs a simple bot on a real level.
- `tools/playtest.tscn` plays many games without a screen with 10 strategies (smart, smart_calls, damage_only, balanced_mix, few_strong, worst_slots, random_a, random_b, support_heavy, cheap) plus human-like noise. Arguments: `--games`, `--out`, `--difficulty`, `--level`, `--from`, `--noise`. Output: `games.jsonl`, `summary.csv`.
- `tools/analyze_playtests.py DIR` writes `report.md`: win rate per level with confidence interval, strategy matrix, how games end, damage per tower, leaks per enemy, per-wave data.
- 1000 games take about 4 minutes. Recorded sets are in `playtests/` (`baseline_1000`, `medium_1000`, `easy_1000`, `hard_1000`, `final_100`).

## Balancing workflow

1. Play at least 1000 games and read the analysis. Do not change numbers yet.
2. Propose changes with the evidence and wait for approval.
3. Edit the tables in `tools/generate_data.gd`, regenerate data.
4. `python3 -I tools/tune_waves.py [--apply]` finds wave scale per level for the target win rate.
5. Rerun playtests, then `python3 -I tools/write_balance_doc.py` to refresh `design/balance.md`.
6. Update tests whose numbers changed.

## Building the APK

1. Raise the version. The name lives in one place, `application/config/version` in `project.godot` (the menu shows it and the Android preset uses it because its `version/name` is empty); `version/code` is in `export_presets.cfg`. The name is SemVer `MAJOR.MINOR.PATCH` (0.x while in beta): MINOR for each approved feature task, PATCH for fixes. `version/code = MAJOR*10000 + MINOR*100 + PATCH` (0.13.0 is 1300). Test builds within one task raise only the code, by 1.
2. `godot --headless --path . --import`
3. `godot --headless --path . --export-debug "Android" build/body-defense-debug.apk` (use the preset name in `export_presets.cfg`).
4. To test on a phone in the same Tailscale network, serve the file over HTTP from a folder and open `http://<tailscale-ip>:8080/<file>.apk` on the phone.

## Screen and icon sizes

| What | Value |
|---|---|
| Orientation | portrait only |
| Project size | 720 x 1280 (`window/size/viewport_*`), stretch mode `canvas_items`, aspect kept: on phones taller than 9:16 (the Galaxy S24 FE is 1080 x 2340) black bars appear above and below, about 200 px of the 1280 on a 1080 x 2400 screen |
| Level view | `Level.VIEW_SIZE` 360 x 640 map units drawn in a sub-viewport and shown at 2x (`Level.SHRINK`); the HUD is drawn on top at 720 x 1280 |
| HUD bars | top `TOP_BAR_HEIGHT` 112 px, bottom `BOTTOM_BAR_HEIGHT` 200 px; the map is scrolled between `SAFE_TOP` 56 and `SAFE_BOTTOM` 100 map units |
| Touch targets | `MIN_TAP` 96 px (48 dp at 2x); slots and enemies use `Level.TAP_RADIUS` 24 map units |
| Cards and panels | build card 316 x 104, tower card 440 x 380, tower info 640 x 660, enemy card 688 x 270 |
| Launcher icon | `icon.png` 512 x 512 (legacy), `adaptive_foreground.png` and `adaptive_background.png` 432 x 432 (108 dp layers) |
| Icon safe zone | Android masks the adaptive icon (circle, squircle, rounded square) and guarantees only the central circle of 66%: 288 px of the 432 px layer. `tools/generate_icon.py` keeps everything within 142 px of the centre and `--check` fails otherwise; `design/icon-options/safe_zone_preview.png` shows the result under two masks |

## Adding or changing text

1. Write the English text in code (`tr("TEXT")`) or in `tools/generate_data.gd` (names, roles, abilities, descriptions).
2. Add a row to `localization/translations.csv` with the translation for every language, then run `godot --headless --path . --import` to rebuild the `.translation` files.
3. `test_localization` in the test runner fails if a `tr("...")` literal, a tutorial text or a data text has no row, or a row has an empty cell.

## Android requirements and performance

- **Minimum Android: 7.0 (API 24)**, set by the Godot 4.7 export template (checked with `aapt dump badging`: `sdkVersion:'24'`, target 36). The game needs OpenGL ES 3.0 (Compatibility renderer) and an arm64 CPU: `armeabi-v7a`, `x86` and `x86_64` are off in `export_presets.cfg`, so 32-bit-only phones cannot install it.
- Size: the debug APK is about 45 MB; the Godot library is 76 MB uncompressed, the music about 1.6 MB per track (imported as QOA).
- Performance rules used so far: the frame rate is capped at 60 (`run/max_fps`), towers redraw only while something animates (aura, mist, ring, shade), the map tissue redraws at 12 Hz, the HUD scroll bar at 10 Hz, sprite frames and music streams are cached. Check with the FPS readout (secret code in the menu).

## Emulator

The Android emulator (`~/Android/sdk/emulator`, AVD `pkbattle-maestro-e2e`) renders the game. Install with `~/Android/sdk/platform-tools/adb install -r build/body-defense-debug.apk`, launch with `adb shell monkey -p com.marcel.bodydefense -c android.intent.category.LAUNCHER 1`, and drive it with `adb shell input tap|swipe` plus `adb exec-out screencap -p`. A long press is `input swipe x y x y 2500`. Start the emulator without a window with `emulator -avd pkbattle-maestro-e2e -no-window -no-audio -no-snapshot -gpu host` (the `swiftshader_indirect` mode fails with a GL uniform limit error and shows black). Screen taps map 1.5x from the 720 x 1280 game size with a 240 px black bar at the top.

## Workflow

- Use OpenSpec (`openspec/changes/<name>/`) for each feature. Past changes: enemy roster and economy, tower roster and damage, level 1 prototype, game audio, levels 2 to 10, balance and difficulty.
- The designer approves finished tasks one by one on the phone; `design/review-checklist.md` tracks the status and each approval raises the MINOR version.
- Commit and push only on request. Commit messages: short imperative subject, then details.
