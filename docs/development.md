# Development

## Setup

- Godot 4.7.2 on the PATH as `godot`.
- Python 3 for the generators and analysis (run with `python3 -I`).
- Android export: SDK, debug keystore and the arm64 template configured in `export_presets.cfg`.

## Tests

```
godot --headless --path . --fixed-fps 60 res://tests/test_runner.tscn   # about 450 checks, expect 0 failures
godot --headless --path . --script res://tools/validate_data.gd
```

`tests/test_runner.gd` has one `test_*` function per feature (data, damage, waves, economy, level, HUD, menu, difficulty, stats, audio). Add checks to the matching section. The secret level-select code (enemy x3, tower x2, enemy x1 on the menu) opens every level for manual testing.

## Bots and playtests

- `--autoplay [--level N] [--call-waves]` runs a simple bot on a real level.
- `tools/playtest.tscn` plays many games without a screen with 10 strategies (smart, smart_calls, damage_only, balanced_mix, few_strong, worst_slots, random_a, random_b, support_heavy, cheap) plus human-like noise. Arguments: `--games`, `--out`, `--difficulty`, `--level`, `--from`, `--noise`. Output: `games.jsonl`, `summary.csv`.
- `tools/analyze_playtests.py DIR` writes `report.md`: win rate per level with confidence interval, strategy matrix, how games end, damage per tower, leaks per enemy, per-wave data.
- 1000 games take about 4 minutes. Recorded sets are in `playtests/` (`baseline_1000`, `medium_1000`, `easy_1000`, `hard_1000`, `final_100`).

## Balancing workflow

1. Play at least 1000 games and read the analysis. Do not change numbers yet.
2. Propose changes with the evidence and wait for approval.
3. Edit the tables in `tools/generate_data.gd`, regenerate data.
4. `python3 -I tools/tune_waves.py [--apply]` finds wave scale per level for the target win rate.
5. Rerun playtests, then `python3 -I tools/write_balance_doc.py` to refresh `design/balance.md`.
6. Update tests whose numbers changed.

## Art and audio

All are generated by scripts: `generate_enemy_sprites.py`, `generate_tower_sprites.py`, `generate_placeholder_art.py` (UI, amino acid icon), `generate_audio.py` (effects and music, `--check` measures them), `generate_icon_options.py` (icon). Screenshot tools: `campaign_screenshots`, `blymphocyte_screenshots`, `card_screenshots`, `neutrophil_screenshots`, `platelet_screenshots`, `tlymphocyte_screenshots`, `tower_screenshots`, `ui_screenshots` (`.tscn` in `tools/`).

## Building the APK

1. Raise the version. The name lives in one place, `application/config/version` in `project.godot` (the menu shows it and the Android preset uses it because its `version/name` is empty); `version/code` is in `export_presets.cfg`. The name is SemVer `MAJOR.MINOR.PATCH` (0.x while in beta): MINOR for each approved feature task, PATCH for fixes. `version/code = MAJOR*10000 + MINOR*100 + PATCH` (0.13.0 is 1300). Test builds within one task raise only the code, by 1.
2. `godot --headless --path . --import`
3. `godot --headless --path . --export-debug "Android" build/body-defense-debug.apk` (use the preset name in `export_presets.cfg`).
4. To test on a phone in the same Tailscale network, serve the file over HTTP from a folder and open `http://<tailscale-ip>:8080/<file>.apk` on the phone.

## Emulator

The Android emulator (`~/Android/sdk/emulator`, AVD `pkbattle-maestro-e2e`) renders the game. Install with `~/Android/sdk/platform-tools/adb install -r build/body-defense-debug.apk`, launch with `adb shell monkey -p com.marcel.bodydefense -c android.intent.category.LAUNCHER 1`, and drive it with `adb shell input tap|swipe` plus `adb exec-out screencap -p`. A long press is `input swipe x y x y 2500`.

## Workflow

- Use OpenSpec (`openspec/changes/<name>/`) for each feature. Past changes: enemy roster and economy, tower roster and damage, level 1 prototype, game audio, levels 2 to 10, balance and difficulty.
- Commit and push only on request. Commit messages: short imperative subject, then details.
