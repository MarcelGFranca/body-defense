## Context

The game has no sound. See `proposal.md` for the motivation and `specs/audio/spec.md` for the requirements. Enemy, tower and level data are resources (`EnemyData`, `TowerData`, `LevelData`), so sound files are referenced from them. The build targets Android, so files must be small and sounds must not pile up.

## Goals / Non-Goals

**Goals:**
- Every requested sound exists and is played from one place.
- Crowds of enemies and towers do not turn into noise.
- No outside audio assets: everything is generated by a script, in a retro 16-bit style that matches the pixel art.

**Non-Goals:**
- A mute button, volume sliders and sounds for the UI.
- Music for other levels, and adaptive music.
- Positional (stereo) sound.

## Decisions

- **An autoload `GameAudio` plays everything.** It owns a pool of 8 `AudioStreamPlayer` voices and one music player. Alternative: an `AudioStreamPlayer` on every enemy and tower. A shared pool makes the voice limit and the 60 ms rule easy to enforce and test, and avoids hundreds of players in a crowd.
- **The 60 ms rule is per sound file.** A pack of rhinoviruses all being hit in the same frame plays one sound, not fifty. Different sounds still play together, up to 8.
- **Sounds are 22,050 Hz mono WAV files generated by `tools/generate_audio.py`.** Alternative: OGG files from a library. WAV needs no encoder, loads fast, and short effects are tiny. The generator uses simple square, triangle and noise waves with pitch slides, the classic 16-bit palette.
- **Each enemy gets its own pitch and character from its data row in the generator.** Viruses are higher and bacteria lower; bosses are lowest and longest. Alternative: three shared sounds for all enemies. The spec asks for sounds that tell enemies apart.
- **Music loops through `AudioStreamWAV` loop points set at runtime** (`LOOP_FORWARD` from sample 0 to the end), so no import settings are needed per file. Alternative: edit the `.import` file. A runtime loop keeps the setting visible in code.
- **Audio keeps running while the game is paused** (the autoload uses the "always" process mode), so the music does not cut off when the pause overlay opens. Effects stop on their own because nothing in the game triggers them while paused.
- **`Engine.time_scale` does not change audio speed.** At 2× game speed, sounds and music keep their normal pitch and tempo.
- **A short blocked sound is played for immune hits** so the player hears that the attack did nothing, matching the shield animation.
- **Volumes live in an `AudioConfig` resource** (`data/audio.tres`), with music quieter than effects.
- **The validator checks that every referenced sound file exists.** A typo in a path fails validation instead of staying silent.

## Risks / Trade-offs

- [Generated sounds may feel thin] → They are placeholders in a retro style that can be replaced by real files later, because they are only paths in data.
- [Area towers and slow enemies can still be repetitive] → The 60 ms rule and the voice limit keep it bounded; volumes are in data.
- [Phones in silent mode] → Android handles this; a mute button is left for a later change.
- [Music loop gap on some devices] → The loop is set on exact sample boundaries; check on a real device.

## Open Questions

- Whether to add a mute button and volume sliders to the HUD. It does not change these specs' data or tasks and can be added after playtests.
